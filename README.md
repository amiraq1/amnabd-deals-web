# amnabd-deals-web

منصة **أم ن عبد** للعروض التوفيرية — موقع ثنائي اللغة (عربي / إنجليزي) يعرض العروض من Supabase.

## Stack

- React 18 + TypeScript + Vite
- Tailwind CSS + lucide-react
- Supabase PostgREST (public, read-only data)

## Scripts

```bash
npm run dev        # dev server
npm run typecheck  # TS strict check (app config)
npm run lint       # eslint
npm run build      # production build
```

## Env

`.env` (ignored) needs `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`.

## اختبارات إصلاحات الإصدار (AMN-002 / AMN-005 / AMN-007)

```bash
npm ci
npm test
npm run typecheck
npm run lint
```

`npm test` يعمل على Node 20+ باستخدام TypeScript الموجود و`node:test`، دون
إضافة حزم. يترجم وحدات التنسيق والتحقق إلى مجلد مؤقت، يشغّل الاختبارات ثم
يحذف المجلد. لا يحتاج Supabase أو متغيرات إنتاج أو اتصالاً بقاعدة بيانات.

- التحقق من ردود API في `src/lib/validate.ts`: عزل الهوية غير الصالحة والتكرارات،
  وتطبيع حقول JSON الاختيارية إلى قيم مجهولة آمنة، وعدم اختلاق السعر أو الأهلية.
- يجب وجود id وslug واسم حقيقي بلغة واحدة على الأقل. الاسم الموجود يُستخدم
  كما هو إذا غابت الترجمة، ولا تُنشأ هوية من slug أو فهرس الصف.
- تحذيرات التطبيق للتشخيص تحتوي أعداداً/رموزاً ثابتة فقط، لا حمولة الصفوف.
- إذا رُفضت بعض الصفوف يظهر تنبيه عام، وإذا كانت مجموعة العروض غير صالحة
  بالكامل يظهر خطأ صريح. Error Boundary أخير يحتوى خطأ عرض غير متوقع.

اختبار واجهة اختياري في بيئة QA فيها Playwright وChromium مثبتان مسبقاً
(ليسا اعتماداً جديداً للمشروع):

```bash
# ابنِ فقط بقيم اختبار صناعية، لا بمفاتيح إنتاج.
VITE_SUPABASE_URL=https://audit-fixture.supabase.co \
VITE_SUPABASE_ANON_KEY=sb_publishable_AUDIT_FIXTURE_NOT_A_REAL_KEY_0001 npm run build
npm run preview -- --host 127.0.0.1 --port 4173
# في طرفية ثانية؛ CHROMIUM_PATH اختياري إذا كانت نسخة Playwright مثبتة:
CHROMIUM_PATH=/path/to/chromium node tests/browser-smoke.cjs
```

اختبار الواجهة يعترض API محلياً ويمنع موارد الطرف الثالث. يمكن ضبط
`AMN_PREVIEW_URL` لعنوان preview آخر و`AMN_SMOKE_REPORT` لحفظ نتيجة JSON.
لا يقرأ بيانات إنتاج ولا يختبر صلاحيات Supabase الحقيقية.

الدفعة الأولى أُتبعت بإصلاحات release المتبقية في PR المراجعة نفسه؛ راجع
قسم الاستكمال أدناه. لا يوجد نشر من فرع الإصلاح في workflow الحالي.

## استكمال مرحلة release

المهام المنفذة على فرع المراجعة: AMN-001/002/003/004/005/007/008/009/018/019.
أُنجز AMN-011 أيضاً ضمن فصل طلبات البيانات عن لغة العرض. لا دمج أو نشر أو
تغيير لبيانات الإنتاج أو سياسات RLS أو migrations.

### نموذج الأهلية المحافظ

- حقول المتطلبات (`student_status`, `card_required`, `new_account`, `phone_required`)
  تُطبّع إلى required/not_required/unknown؛ yes/no قيم قديمة مرادفة وليست حقائق مختلفة.
- applicant_type نموذج مستقل: any/student/startup/organization/individual/multiple/unknown.
  individual لا تعني any، والقيم غير المعروفة لا تُرقّى إلى أهلية عامة.
- فلتر «مفتوحة للجميع» يتطلب **تأكيد مراجعة صريحاً** `eligibility.open_to_all: "yes"`
  داخل JSON الموجود (ليس عموداً أو migration جديداً). لا يضيف التطبيق هذا الإثبات إلى الإنتاج.
- ويتطلب أيضاً applicant_type=any، وعدم اشتراط طالب أو حساب جديد، وحالة بلد
  worldwide/global/all/unrestricted مع قائمة قيود بلدان فارغة. التعارض أو المجهول يُستبعد.
- يجب ألا يضيف المسؤول التأكيد إلا بعد مراجعة مصدر يثبت نطاق الأهلية والقيود.
  لا يُستنتج من النص أو غياب شرط الطالب، ولا من مجرد وجود رابط رسمي.
- قد تكون نتائج هذا الفلتر فارغة للبيانات القديمة حتى تُوثّق الأهلية؛ هذا أفضل من
  اعتبار المجهول متاحاً للجميع. بطاقة/هاتف يظلان متطلبين منفصلين لا ضماناً لأهلية كل فرد.

### التحميل والتخزين والتوثيق

- العروض والأدلة والإعدادات تُطلب وتستقر بصورة مستقلة، بمهلة 10 ثوانٍ وإلغاء.
  فشل مورد اختياري لا يمنع العروض، وإعادة المحاولة لا تعيد جلب الموردين الآخرين.
- 404 للعرض يأتي فقط بعد نجاح تحميل العروض وعدم العثور على slug؛ خطأ الشبكة/البيانات
  له رسالة وإعادة محاولة. لا تُعرض تفاصيل SQL أو الأخطاء الخام.
- تغيير اللغة يترجم واجهة الحالة محلياً دون إعادة جلب Supabase؛ تفضيل اللغة يعمل
  في الذاكرة حتى عند رفض getter/getItem/setItem الخاص بالتخزين المحلي.
- لا يفتح التطبيق جلسة مستخدم؛ يستعمل عميل PostgREST 2.109.0، الموجود سابقاً
  كاعتماد انتقالي لـSupabase SDK، وأصبح اعتماداً مباشراً بدلاً من SDK الشامل.
  السبب: وحدة Auth في SDK تقرأ localStorage عند الاستيراد حتى مع تعطيل persistence.
  لا تعديل لملفات node_modules أو تعطيل لسياسة المتصفح. لا Auth/Realtime في حزمة الموقع.
- الشارة تميز المدعوم/الجزئي/غير المدعوم/المجهول، وتعرض تاريخ المراجعة. قوة الدليل
  ليست ضمان استمرار العرض أو أهلية الفرد، وعدد الحقول غير المثبتة ليس شهادة اكتمال.
- hash غير صحيح أو ترميز معطوب أو أجزاء زائدة لا يسقط التطبيق. slug مقطع URL واحد
  بلا فراغات/محارف تحكم أو فواصل مسار، مع دعم العربية وفك الترميز مرة واحدة فقط.

### بيئة البناء

كل `vite build` يفحص URL ومفتاحاً عاماً: HTTPS، دون credentials/query/hash،
وpublishable key أو JWT بصفة anon. مفاتيح sb_secret_ وservice_role مرفوضة.
التحقق يراجع الشكل/الصفة فقط، **لا يثبت صحة توقيع JWT أو صلاحيات مشروع الإنتاج**.
السجلات تذكر رموز الخطأ فقط دون قيم المفاتيح. HTTP على loopback مسموح للتطوير فقط.
غياب الإعدادات في التطوير يعرض واجهة خطأ قابلة للفهم بدلاً من خطأ استيراد وشاشة فارغة.

```bash
npm test
npm run test:build-env
npm run typecheck
./node_modules/.bin/tsc --noEmit -p tsconfig.node.json
npm run lint
```

`test:build-env` يجرب ست حالات رفض وحالة نجاح بقيم صناعية، ويؤكد عدم إنتاج
artifact في حالات الرفض وعدم ظهور المفاتيح في المخرجات. لا يستعمل أسرار الإنتاج.
اختبارات الواجهة الموسّعة في `tests/browser-smoke.cjs` تشمل الفلاتر، وفشل كل مورد
وإعادة المحاولة والمهلة، والتوثيق، والتخزين المحظور، والتوجيه، وعدم الجلب عند تغيير اللغة.

لفحص واجهة التطوير عند غياب البيئة أيضاً، شغّل dev بقيمتين فارغتين على منفذ آخر،
ثم مرّر `AMN_DEV_PREVIEW_URL` للاختبار الاختياري:

```bash
VITE_SUPABASE_URL='' VITE_SUPABASE_ANON_KEY='' npm run dev -- --host 127.0.0.1 --port 4174
# مع بقاء preview لنسخة البناء الصناعية على 4173:
AMN_DEV_PREVIEW_URL=http://127.0.0.1:4174 CHROMIUM_PATH=/path/to/chromium node tests/browser-smoke.cjs
```

اختبارات الجودة هنا محلية؛ لم تُضف حواجز CI إلى workflow ضمن release، ولم يُنجز
SEO/SSG أو بقية تحسينات quality/product/discoverability/later. لا تُغلق تلك المهام تلقائياً.

## دفعة تحسين التجربة: الفئات والبطاقات ونسخ الرابط

- فئات سريعة من `category.value` فقط، مع عدد إجمالي للعروض في كل فئة، وخيار مستقل
  لغير المصنف. العدادات إجمالي الفئة قبل البحث/فلاتر الأهلية؛ عدد النتائج أسفل البحث
  هو العدد بعد تطبيق جميع الشروط. لا تصنيف بالاستنتاج من الوصف ولا دمج دلالي لفئات مختلفة؛
  يوحد اختلاف الحالة والمسافات فقط، وتُحفظ أسماء الفئات الموجودة دون ترجمة مختلقة.
- الفئة والبحث وفلاتر الطالب/البطاقة تعمل معاً. زر المسح يعيد الجميع، وحالة عدم وجود
  نتائج تتضمن مسار استعادة مباشر. حالة اختيار الأزرار وفتح الفلاتر وعدد النتائج معلنة دلالياً.
- البطاقة تعرض عدد المنافع الإضافية والسعر المسجل ودورة فوترة معروفة وموعد التسجيل.
  المفقود/غير الصالح يبقى «غير معلوم». الصفر ليس وعداً بمجانية شاملة أو دائمة.
  لا حساب لنسبة التوفير: النموذج الحالي لا يثبت خطة/عملة/دورة السعر المرجعي بصورة مستقلة.
- الموعد يُعرض فقط عند `deadline.status=known` وتاريخ صحيح؛ التاريخ المجرد يبقى كما هو،
  والتوقيت الصريح يحتفظ بـZ/offset. لا استنتاج لمنطقة زمنية ولا عد تنازلي أو ادعاء دوام العرض.
  صلاحية المنفعة لا تستخدم كموعد تسجيل، ولا يُستنتج استمرار العرض من تاريخ الموعد.
- زر نسخ في صفحة التفاصيل ينسخ رابط العرض نفسه مع الحفاظ على مسار الاستضافة وحذف query.
  يستخدم Clipboard API عند الطلب فقط؛ لا قراءة للحافظة ولا مشاركة خارجية أو تتبع.
  إشعار نجاح معلن يختفي بعد 4 ثوانٍ؛ الرفض/غياب API/تعليق الإذن لأكثر من 5 ثوانٍ
  يوفر حقلاً للنسخ اليدوي وإعادة المحاولة، دون ادعاء نجاح غير مؤكد.
- اختبار عرض 320px كشف تجاوزاً في شريط التنقل الإنجليزي؛ أصبح يلتف على الشاشة الضيقة
  دون إخفاء اسم الموقع أو إجراءات التنقل. تحسنت مؤشرات التركيز والتفاف بطاقة العرض أيضاً.

لا تغييرات في backend أو البيانات أو RLS أو migrations أو workflow، ولا اعتماديات جديدة.
هذه دفعة جزئية: لا ملخص قرار أو فصل زر التسجيل عن المصدر بعد، ولا حفظ للفلاتر في الرابط،
ولا فرز أو مفضلة أو مشاركة Web Share أو SEO/SSG أو تعميم إصلاحات الوصول لكل المكونات.

اختبارات وحدات الدفعة ضمن `npm test`. لفحص المتصفح الاختياري، مع تشغيل preview
لنسخة بناء صناعية كما في القسم السابق:

```bash
CHROMIUM_PATH=/path/to/chromium node tests/ux-browser.cjs
CHROMIUM_PATH=/path/to/chromium node tests/browser-smoke.cjs
```

يتطلب الاختبار الاختياري Playwright في بيئة QA فقط، ولا يضيفه كاعتماد للمشروع.
يستخدم بيانات صناعية ويعترض API ويمنع موارد الطرف الثالث، ويُحاكي الحافظة دون قراءتها.
يمكن حفظ النتائج عبر `AMN_UX_REPORT=/path/to/results.json`.

## المرحلة الثانية: البحث الموسّع وحالة الرابط والفرز الآمن

هذه متابعة تصحيحية للتنفيذ الأولي المدموج في PR #4، مبنية على مكونات PR #3.
النطاق استكشاف على العميل فقط؛ لا مفضلة أو PWA أو تغيير بيانات أو RLS أو migrations
أو workflow أو اعتماديات. لا دمج أو نشر ضمن هذه الدفعة.

### البحث ومصدر الحقيقة

- `discovery.ts` يبني corpus عبر `useMemo` عند تغيّر مصفوفة العروض فقط: الاسم والوصف
  باللغتين، الفئة ومسمّياتها الموجودة أو «غير مصنّف»، وأوصاف المنافع وأنواعها ووحداتها
  ومددها وفق دوال العرض المعتمدة. لا افتراض لحقل tags أو مزوّد مستقل.
- `normalize.ts` مصدر التطبيع الوحيد: الهمزات، ى→ي، ة→ه، التشكيل والتطويل،
  الأرقام ٠–٩، حالة الأحرف والمسافات. `c++` و`c#` و`.net` رموز متمايزة.
- تُولَّد الصيغة المدمجة فقط من فاصل داخلي بين حروف/أرقام: `gpt-4 → gpt4`
  و`node.js → nodejs`، على corpus والاستعلام معاً. لذلك تعمل المطابقة بالاتجاهين
  دون اختراع صيغة مفصولة من `gpt4` أو `mp3` أو `h264`.
  هذا بديل متعمّد لقاعدة «2–6 حروف ثم 1–3 أرقام»؛ تلك القاعدة تشمل mp3 وh264 أيضاً.
- OR بين صيغ الكلمة، AND بين كلمات الاستعلام، والفارغ يعيد الجميع.
  المطابقة substring (`includes`)، وليست حدود كلمات: قد يطابق `gpt4` النص `gpt40`.

### عقد FilterState والرابط

ترتيب التسلسل القانوني: `q → category → uncategorized → applicant → card → sort`.

| المعامل | القيم والمعالجة |
| --- | --- |
| q | إزالة محارف التحكم، trim وقصّ إلى 120 محرف Unicode؛ الافتراضي فارغ |
| category | مفتاح موجود في البيانات؛ الغياب يعني كل الفئات، أما `category=all` فهي فئة فعلية |
| uncategorized | `1` فقط يعني غير مصنّف؛ غيره تشخيص خطأ |
| applicant | all / student / any؛ غير الصالح يعود إلى all |
| card | all / not_required؛ غير الصالح يعود إلى all |
| sort | default / reviewed / deadline؛ غير الصالح يعود إلى default |

- `URLSearchParams.get` يعني **أول قيمة**، لا أول قيمة صالحة. فك الترميز مرة واحدة؛
  تجاهل المعاملات المجهولة وحذف الافتراضي من الرابط. فصل المسار عند أول `?` فقط.
- فئة غير معروفة: `invalidCategory` وتنبيه مرئي دون تطبيق فلتر الفئة.
  اجتماع category مع uncategorized=1 تعارض، لا اختيار صامت لأحدهما.
  التشخيصات لا تُكتب في التسلسل الجديد؛ أي تغيير مقصود ينظّفها، وزر المسح يعيد `#/`.
- category تبقى pending حتى نجاح تحميل العروض؛ لا تنبيه مبكر. نجاح مجموعة فارغة
  يتيح الحكم على الفئة، بينما فشل الجلب يبقى خطأ مورد لا خطأ فئة.
- `parse → serialize → parse` ثابت للحالة القانونية؛ التشخيصات تُنظَّف عمداً ولا يُدّعى
  حفظ الحالة غير الصالحة حرفياً.
- البحث ظاهر فوراً، مع حفظ المسافات أثناء الكتابة؛ الرابط يُنظَّف بعد debounce قدره 250ms
  عبر replaceState. الفئة/الأهلية/البطاقة/الفرز/المسح تستخدم pushState.
  حالة React تُحدَّث يدوياً لأن هاتين الدالتين لا تطلقان popstate.
- يُلغى المؤقت عند الرجوع/التقدم/hashchange أو المغادرة. قبل فتح عرض/دليل تُحفظ مسودة
  البحث الأخيرة في مدخل الاستكشاف الحالي، ويعيد «كل العروض» الحالة نفسها.
  ازدواج popstate/hashchange يُمنع بمقارنة آخر hash مطبّق، لا بحارس دائم يمنع الرجوع إليه.
- زر مشاركة البحث مستقل عن نسخ العرض؛ ينسخ أحدث حالة ويحذف query خارج hash، ويقدّم
  حقلاً قابلاً للتحديد عند رفض الحافظة دون ادعاء نجاح. لا طلب Supabase إضافي لتغييرات التحكم.

### الفرز ومرجعية UTC

`sortDeals(deals, sortBy, referenceNow)` دالة نقية، المرجع إلزامي ولا تقرأ الساعة داخلياً.
ترجع نسخة وتحتفظ بترتيب المصدر عند التعادل. مرجع غائب/غير صالح يرمي RangeError.
الساعة في HomePage خارج الدالة، وتتحدث كل دقيقة وعند عودة الصفحة للظهور.

- default: ترتيب المصدر.
- reviewed: `review.reviewed_on` الصحيح تنازلياً ثم المجهول، بالمحلل الصارم نفسه.
  تنبيه حدود API: طبقة validate الحالية تقبل تاريخ مراجعة تقويمياً فقط؛ التوقيت الصريح
  مدعوم في دالة الفرز واختباراتها لكنه يُطبَّع إلى مجهول عند التحميل الحالي. لم نوسّع
  طبقة validate لأنها خارج خريطة الملفات المسموحة.
- deadline: **حصراً** `registration.deadline` مع status=known، بأربع مجموعات معلنة في الواجهة:

| المجموعة | القاعدة | الترتيب |
| --- | --- | --- |
| 1 | توقيت صريح صالح ≥ referenceNow | الأقرب أولاً |
| 2 | تاريخ تقويمي صحيح ≥ يوم المرجع UTC | تصاعدي |
| 3 | توقيت سابق أو يوم تقويمي أسبق | الأحدث أولاً |
| 4 | مجهول/متعارض/غير صالح | ترتيب المصدر |

المجموعة 1 تسبق 2 دائماً؛ ليس هذا ترتيباً زمنياً عالمياً بينهما ولا إثباتاً لاستمرار العرض.
التقويمي يخضع لـ round-trip صارم؛ تُرفض 2026-02-30 والسنة غير الكبيسة. يُعالَج حتى
نطاق السنوات 0000–0099 دون تحويل ضمني إلى 1900. التوقيت يتطلب Z أو ±HH:MM مع تحقق
الساعة والدقيقة والثانية والمنطقة. يُرفض -00:00 لأنه يعني منطقة غير معلومة، وتُقص كسور
الثانية إلى دقة millisecond. لا مقارنة نصية بـ toISOString تتجاهل offset الأصلي.

بداية اليوم UTC للتاريخ التقويمي **مفتاح ترتيب فقط** للمنقضي/المراجعة، لا ساعة انتهاء
مختلقة. تعادل هذا المفتاح مع توقيت دقيق يُحسم بترتيب المصدر. لا افتراض 23:59:59، ولا
وصف العرض بأنه منتهٍ أو دائم أو مفتوح انطلاقاً من الموعد وحده.
