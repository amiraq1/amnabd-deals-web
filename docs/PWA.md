# PWA خفيفة قابلة للتثبيت

النسخة الحالية قابلة للإضافة إلى الشاشة الرئيسية في المتصفحات الداعمة. يولّد `postbuild` ملف `manifest.webmanifest` وأيقونات PNG بمقاسي 192 و512 من `public/favicon.svg`، وأيقونة maskable بخلفية كاملة. لا حزمة أو خدمة خارجية جديدة مطلوبة.

## البيانات لا تأتي من نسخة قديمة

لا يخزّن عامل الخدمة طلبات Supabase/PostgREST، ولا HTML صفحات العروض أو المجموعات أو SEO. التنقلات تستعمل `cache: 'no-store'`؛ عند فشل الشبكة تظهر صفحة offline صريحة لا تتضمن بيانات عروض، لا نسخة قديمة من الكتالوج.

عميل PostgREST نفسه يستعمل `networkOnlyFetch` مع `cache: 'no-store'` لمنع HTTP cache أيضاً. ولا تُعرض قيمة المورد التي تحتفظ بها أداة التحميل أثناء إعادة المحاولة أو بعد الخطأ؛ تُعرض حالة تحميل أو رسالة خطأ حتى تنجح قراءة شبكة جديدة.

قائمة cache محصورة عند البناء في أصول Vite ذات content hash، وأيقونات ذات إصدار، وصفحة offline ذات بصمة. لا `stale-while-revalidate` ولا cache لبيانات API أو الخطوط الخارجية. إذا انقطع الاتصال أثناء فتح التطبيق، تُخفى بيانات الذاكرة أيضاً. عودة الاتصال تعيد تحميل الصفحة للحصول على بيانات حديثة بدلاً من إعادة إظهار الكتالوج السابق.

## المفضلة والتنبيه المحلي

مفاتيح المفضلة المحلية وترحيلها ومزامنتها بين التبويبات لم تتغير. يبقى قسم المفضلة التي تنتهي خلال 14 يوماً معتمداً فقط على `ends_at` المسجّل والصالح والمستقبلي.

لا طلب إذن إشعارات ولا push أو مؤقت خلفي في هذه الدفعة؛ لا ندّعي إمكان ضمان تنبيه عندما يكون التطبيق مغلقاً دون بنية تسليم مناسبة. قسم قرب الانتهاء المحلي باقٍ كما هو، ولا تُستنتج تواريخ من النصوص.

## التثبيت والتحديث

تعرض المتصفحات الداعمة زر التثبيت؛ على iOS يمكن الإضافة إلى الشاشة الرئيسية من قائمة المشاركة في Safari. لغة الرابط والمفضلة والمسارات وSEO تبقى منطق التطبيق نفسه؛ صفحة offline تحترم `?lang=` قبل التفضيل المحلي. `vite.config.ts` يبقى `base: '/'`.

العامل الجديد ينتظر ولا يفرض إعادة تحميل مفاجئة. عند ظهوره يُعرض زر «تحديث التطبيق»؛ اختياره يفعّل العامل الجديد ثم يعيد تحميل الشبكة. تزال caches القديمة للتطبيق وحدها ولا تُمس مفاتيح localStorage.

## فحوص البناء

`npm test` يتضمن اختبارات بناء PWA والعامل: تجاوز API، رفض HTML الكتالوج في cache، التنقل الشبكي، fallback الصريح، انتظار التحديث وتنظيف cache القديم.

بعد كل build يعمل `node scripts/verify-pwa.mjs` آلياً ليفحص manifest والأيقونات وقائمة cache وبيانات PWA في جميع صفحات التطبيق المولدة. لا يُسجّل العامل في Vite dev؛ اختبر نسخة `vite preview`.
