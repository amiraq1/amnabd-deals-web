# فحص وتحسين واجهات العروض

## المهمة والنطاق

تحسين عرض البطاقة والتفاصيل والبحث والفئات والفلاتر وشريط الجوال والفوتر. الأساس: `91e60a13fed6ed6d4def8f68168d7333b47beec9`، والفرع `design/offer-cards-polish`. لا دمج ولا نشر.

قُرئت README وDEALS وsample-deal وطبقة validate قبل التعديل. اكتُشفت المكونات من المستودع، ولم تُفترض أسماؤها. اسم «نبض» الظاهر في النسخة الحالية لم يُغيّر. استُخدمت المراجعة النصية المرفقة كمرجع إضافي، لا كتصحيح يُنسخ بلا تحقق.

لم يوجد `.env`. نجح `npm ci`، وشُغّل dev محليًا ثم preview لبناء بقيم الاختبار الصناعية الموثقة في README. جميع صور المتصفح تستخدم اعتراض API محليًا؛ لا اتصال ببيانات Supabase الفعلية أو تعديل لها. Playwright وChromium من بيئة QA فقط، ولا اعتماديات جديدة.

### الاتجاه البصري

الحفاظ على السمة الحالية دون إضافة وضع داكن/فاتح أو هوية جديدة. الأخضر الأساسي `#10b981` من favicon/config، مع أسطح slate محايدة وحدود 1px وحواف 12–16px. لا صور للجهات ولا خطوط شبكة ولا SALE أو تقييمات أو عدادات مصطنعة.

```text
حرف أول محلي + اسم (سطران) + الفئة المسجلة (أيقونة زخرفية)
المنفعة الأولى: صياغة benefitAmount، أو وصفها الحرفي، أو غير معلوم
الشرط الحرفي إن وجد، وإلا headline_value/الوصف (حتى 3 أسطر)
عدد المنافع الإضافية
السعر ودورته / البطاقة / لمن / موعد التسجيل
حالة دعم الأدلة بأيقونة ونص + آخر مراجعة
رابط تفاصيل أساسي + حفظ ثانوي
مقارنة ومصدر كإجراءات ثانوية
```

### نموذج البيانات والصدق

- `headline_value` و`key_condition` و`use_cases` تمر بالفعل عبر validate. الأولان يُعرضان حرفيًا في الملخص؛ البطاقة لا تحسب منهما رقمًا أو خصمًا. بقي استهلاك use_cases القائم كما هو.
- المنفعة الرئيسية تستخدم أول منفعة ودالة `benefitAmount` الموجودة، مع وصف المنفعة عند غياب رقم. السعر والموعد عبر `recordedPrice` و`registrationDeadline`، والبطاقة عبر `requirementLabel`.
- الصفر يظل سعرًا/قيمة مسجلة، لا «مجاني للأبد» أو توفيرًا. لا حساب لسعر قبل/بعد.
- `eligibilitySummary` يعيد استخدام `isOpenToAll` نفسه؛ `any` وحدها لا تنتج «مفتوح للجميع».
- أسماء الفئات من `categoryLabel` القائمة فقط. الخريطة الجديدة تخص الزخرفة؛ الفئة غير المعروفة محايدة، بلا ترجمة أو استنتاج من الوصف.
- حالات الأدلة الأربع من `evidenceStatus` و`evidenceLabel` القائمتين. لم يُحوّل `verified` أو `verdict` إلى `supported`؛ توثيق المراجعة ودعم الأدلة ليسا مترادفين.
- لم يُعدّل `dealTiming` أو الفرز أو حالة الرابط. أُخفي اختصار الاستعجال من الرئيسية في طبقة العرض، وأُعيدت تسمية ترتيب التاريخ بصياغة مسجلة. تفاصيل الحالة تستخدم `offerStatusLabel(review.offer_status)` لا استنتاجًا زمنيًا.

## التنفيذ

- خُففت مقدمة الجوال بإخفاء النصوص التعريفية المكررة وتصغير الاختصارات؛ لا إخفاء لحقائق العرض. رُفعت نصوص الفوتر والتحكم إلى 14px، وصُححت رسالة قاعدة العروض الفارغة لتختلف عن عدم تطابق الفلاتر.
- هياكل تحميل للمقدمة والتحكم وبنية البطاقة؛ تقلل اختلاف المقاسات، وليست دعوى بقياس CLS أو انعدامه.
- مكونات عرض مشتركة: `OfferFacts`, `CategoryBadge`, `DealCardSkeleton`, `IsolatedText`.
- دوال عرض نقية في `offerPresentation.ts`: الحرف الأول، لون زخرفي ثابت، احتياطي الفئة، عرض أول منفعة، وصياغة أهلية محافظة.
- عزل مجموعات الأرقام والعملات واللاتينية وتواريخ ISO داخل bdi، دون تغيير النص المسجل.
- الشعار الأولي بست درجات في tailwind tokens، وجميع أزواج النص/الخلفية ≥4.5:1. حدود عناصر التحكم ذات المعنى ≥3:1. المجهول رمادي مع نص، لا إشارة إيجابية أو تحذير أحمر.
- بطاقات متساوية ضمن الشبكة، مع زر الإجراء في الأسفل. الأسماء سطران والوصف ثلاثة أسطر؛ النص الكامل في التفاصيل.
- أبقي قياس الشريط عبر ResizeObserver والمتغير `--amnabd-mobile-actions-height`، وsafe-area، وحد 640px، وz-40 للشريط وz-30 للصعود. لم يُستبدل القياس بتعويض ثابت.
- أزيلت طلبات الخطوط والشعارات الخارجية وصورة متابعة F6S فقط؛ بقي رابط المتابعة ووجهته وtarget/rel.
- لم تتغير backend أو البيانات أو RLS أو migrations أو workflows أو إعدادات النشر أو validate/normalize/discovery/savedDeals/filterState، ولا ملفات الاعتماديات. مولدات SEO/PWA القائمة شُغّلت ضمن build ولم تُعدّل.

### مصفوفة المتصفح والصور

56 سيناريو قبل و56 بعد: الرئيسية والتفاصيل والتحميل والفراغ والخطأ عند 320 و375 و768 و1280، بالعربية والإنجليزية، ثم تفاصيل الحالات الإضافية عند 320. توجد أيضًا صور البطاقة والفئات والفلاتر المفتوحة وشريط الجوال، وصور لكل حالة بيانات في البطاقات، وتكبير نص 200% للعربية والإنجليزية عند 320.

البيانات صناعية وتشمل سجل قرار مكتملًا، ونسخة مجهولة من sample-deal، وأسماء عربية/إنجليزية طويلة جدًا، وفئة طويلة واحتياطي غير مصنف، و0/1/7 منافع، ومواعيد مستقبلية/سابقة/مجهولة، وأسعار null/0/موجبة بدورات مختلفة، وحالات الأدلة الأربع، ومتطلبات البطاقة الثلاث، ومحفوظ/غير محفوظ.

الاختبار يتحقق من: عدم التمرير الأفقي، وعدم العناصر التفاعلية المتداخلة، وأهداف لمس ظاهرة ≥44px ارتفاعًا، وتركيز لوحة مفاتيح ظاهر بعرض ≥2px، والنقر الفعلي على التفاصيل، وتبديل aria-pressed للقلب، وعدم طلب طرف ثالث، وعدم أخطاء JavaScript، وقياس الشريط وترتيب z وعدم تداخله مع الصعود، وإعادة قياسه عند تكبير النص وتنظيف المتغير بعد المغادرة.

تمت مراجعة بصرية يدوية للقطات ممثلة، خصوصًا العنوان الضيق والبطاقة المجهولة والأسماء الطويلة وشبكة سطح المكتب والفلاتر وحالات الصفحة؛ ليست هذه دعوى بأن كل صورة إضافية راجعتها يدويًا، ولا تدقيق وصولية بشري شاملًا.

### اختبارات المتصفح القديمة: ليست خضراء

لم تُحذف أو تُضعّف تأكيداتها لتمريرها. أُعيدت المقارنة على البناء الأصلي المحفوظ لعزل الأعطال السابقة:

| الحزمة | النتيجة/المانع |
| --- | --- |
| browser-smoke.cjs | توقفت عند محدد `Switch to English`؛ اسم الزر الحالي مختلف. الفشل نفسه في الأصل |
| phase2-browser.cjs | تتوقع معاملات حالة الرابط في hash؛ التطبيق الحالي يستخدم المسار/search. الفشل نفسه في الأصل |
| phase3-browser.cjs | تتوقع تسمية حفظ قديمة `Save …`، فتتوقف قبل بقية الحالات. الفشل نفسه في الأصل؛ لا يعني ذلك إثبات سلامة التخزين |
| ux-browser.cjs | الأصل فشل في الحقائق المفقودة. بعد التحسين تجاوز اختبارات الفئات والبحث وحقائق البطاقة والمجهول، ثم فشل بتوقع رابط نسخ hash قديم بدل الرابط canonical الحالي مع اللغة |

عُدّل محدد التاريخ في UX فقط لاستهداف bdi الخاصة بالتاريخ بعد إضافة عزل أرقام أخرى؛ بقي التأكيد على التاريخ الدقيق وكافة التأكيدات الأخرى. كذلك استُبدلت تأكيدات صورة F6S باختبار الوجهة وtarget/rel والنص ثنائي اللغة و44px وعدم تحميل صورة، اتساقًا مع طلب عدم الطرف الثالث.

## ما لم يُتحقق منه وما أُجّل

- لا اختبار على Supabase الإنتاجية أو صحة المصادر الرسمية/شروطها أو RLS، ولا نشر، ولا ادعاء نجاح اختبارات legacy المتوقفة أو بقية حالاتها التي لم تصل إليها.
- عيب المخزنين يحتاج قرارًا لتوحيد المحفوظات/المفضلة في مهمة منفصلة واختبارات مزامنة كاملة، لا ترقيعًا بصريًا أو تخفيف اختبارات.
- P2: مراجعة كثافة البطاقة بمحتوى إنتاج واقعي، واختبار قارئ شاشة وأجهزة/متصفحات فعلية، وتحديث حزم browser القديمة لعقد التوجيه الحالي مع الاحتفاظ بتغطيتها، ومراجعة بقية صفحات المفضلة/المقارنة/المجموعات.
- P2 اختياري منفصل: خط عربي مرخص self-hosted في public مع font-display: swap بعد موافقة المالك؛ لم يُضف خط أو CDN بصمت.
- تحذيرات تدقيق npm للاعتماديات القائمة لم تُعالج بتغيير حزم خارج النطاق.
